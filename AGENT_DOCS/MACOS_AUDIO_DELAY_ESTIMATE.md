# macOS 오디오 재생 딜레이 추정

구현 예정인 Apple 전용 추정 방식이다. Windows/Linux 경로는 유지한다.
실제 출력과의 고정 오프셋은 허용하고, 상대적인 재생 진행률을 추정한다.

## 기준점

콜백 종료를 이번 버퍼의 소비 시작점으로 가정한다. 종료 시 함께 기록한다.

- `S`: 실제 출력 장치의 `AudioDeviceGetCurrentTime()`으로 얻은 `mSampleTime`
- `F`: 이번 콜백에서 처리한 프레임 수
- `C`: 이번 콜백까지 포함한 누적 프레임 수
- `R`: PDJE 샘플레이트(프레임/초)
- `Rd`: 장치 샘플레이트(프레임/초)

## 계산

조회 시 같은 출력 장치의 현재 `mSampleTime`을 얻는다.
Mach tick이나 글로벌 시각으로 변환하지 않는다.

```text
진전 프레임 = (현재 mSampleTime − S) × R / Rd
남은 프레임 N = clamp(F − 진전 프레임, 0, F)
추정 재생 위치 = C − N
```

기존처럼 람다가 남은 프레임 수를 `uint32_t`로 반환한다.
실제 조회 시점에 계산한다. 콜백에서 계산한 값을 저장만 하면 콜백 사이에 감소하지 않는다.

## 제약

- 실제 하드웨어 큐 길이를 측정하는 방식은 아니다.
- 콜백 종료부터 실제 재생 시작까지의 고정 지연은 보정하지 않는다.
- 기준 sample time과 프레임 정보는 같은 콜백의 값으로 일관되게 읽는다.
- 조회 성공과 `kAudioTimeStampSampleTimeValid`를 확인한다. 실패한 값은 계산에 사용하지 않는다.
- 정지·재시작·장치 변경·샘플레이트 변경 또는 sample time 역행 시 기준점을 초기화한다.
