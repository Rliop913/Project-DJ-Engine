# macOS 오디오 재생 딜레이 추정 명세

상태: 구현 전 요구사항.

## 목적과 범위

- Apple 경로에서 상대적인 재생 진행률을 추정한다. Windows/Linux 경로는 변경하지 않는다.
- 실제 출력과의 고정 오프셋은 허용한다. 하드웨어 큐 길이의 직접 측정과 고정 지연 보정은 범위 밖이다.
- Mach tick이나 글로벌 시각 대신 출력 장치의 `mSampleTime`을 기준으로 한다.

## 추정 모델

콜백 종료를 이번 버퍼의 소비 시작점으로 간주한다.

| 값 | 의미 |
| --- | --- |
| `S` | 콜백 종료 시 출력 장치의 sample time |
| `F` | 해당 콜백의 프레임 수 |
| `C` | 해당 콜백까지 포함한 누적 프레임 수 |
| `R`, `Rd` | PDJE와 장치의 샘플레이트(프레임/초) |

조회 시점의 같은 장치 sample time을 `s`라 할 때:

```text
진전 프레임 = (s − S) × R / Rd
미소비 프레임 N = clamp(F − 진전 프레임, 0, F)
추정 재생 위치 = C − N
```

## 인터페이스와 유효성

- 기존 람다 인터페이스를 유지하고, 조회 시점의 미소비 프레임 수를 `uint32_t`로 반환한다.
- 기준점과 프레임 정보는 같은 콜백에 속하는 일관된 값이어야 한다.
- 유효하지 않은 sample time은 추정에 사용하지 않는다.
- 정지·재시작·장치 변경·샘플레이트 변경·sample time 역행 시 이전 기준점을 무효화한다.

## 검증 기준

- 동일 샘플레이트에서 `s = S`이면 `N = F`, `s − S = F`이면 `N = 0`이다.
- 반환값은 `0`부터 `F`까지이며, 샘플레이트가 달라도 PDJE 프레임 단위로 반환한다.
- 콜백 지터는 추정 오차에 반영된다. 실제 출력과의 절대 위치 일치는 요구하지 않는다.
